# Round 5 (2026-11-13): the demo speaks Chinese and Korean, and `--quantize-variable` gets its honest protected mode

## What this round did, in one paragraph

Round 4 left two items: the demo's live preview was Japanese-only, and
the gvar-aware design study's M3 exemption existed only as a probe.
Both land here. The demo now has a **ja/zh/ko language switch on the ε
preview**: per-language subset WOFF2 assets (Noto Sans SC/KR, same
round-3 pattern as Japanese), per-language sample text and charsets,
and full-font grid references for SC/KR measured from scratch (§1).
`tools/glc.py` gains **`--quantize-variable-protected`**: build
unprotected → instance at the fvar peaks → exempt the tail glyphs →
rebuild → verify against the 2·grid bound, with the Arm A {400,700}
reference price printed next to it (§2). The protected single file
(3,974,768 B, peak error 138 → 16 units) still loses to the two static
instances (3,544,244 B), so the round-4 verdict stands — protected
mode ships as a labelled experimental option, not a recommendation.
This round was interrupted mid-flight and resumed from the WIP commit;
§3 records what was verified, not redone.

**Verification.** All 18 assets open as valid WOFF2 and cover their
language's sample text completely (checked by cmap). The regenerated

with all six grids each; the embedded JavaScript passes
`node --check`. One disclosed gap, same as round 3: no live

subsetter output is not bit-stable across runs at this scale; the
rendered result is unchanged, so the new numbers are what the demo
now shows.

## 2. `--quantize-variable-protected`: M3 exemption in `tools/glc.py`

Implementation (`tools/glyphcodec.py`, `tools/glc.py`):
`process_variable_font` takes an `exempt` set — exempt glyphs keep
their exact default outlines (their interpolated error collapses to
~0; everything else, including the hinting strip, still applies).
`process_variable_font_protected` builds the unprotected font,
instances stock vs quantised at the fvar peaks
(`vf_sample_locations`: default, min/max, gvar tuple peaks, midpoints,
corners — for this single-axis font that collapses to wght 100/500/900),
exempts every glyph over the 2·grid bound, rebuilds, and re-measures
(up to 3 rounds). `vf_glyph_errors_at` instances both fonts and
compares point by point after a glyf serialisation round-trip, the
same convention as the round-3/4 harness (in-memory interpolation
alone reports half-unit errors). The CLI also prints the Arm A
{400,700} reference price next to the protected size, and the module
docstring now carries the measured numbers the `--help` text points
at. A small fix in `arm_a_reference`: all fvar axes are now pinned at
their defaults when instancing (pinning wght alone would leave a
multi-axis font variable and misprice the "instance"); a no-op for
single-axis Noto Sans JP, verified as such below.

Measured on Noto Sans JP [wght], grid 8 (re-run from the final code;
see §3):

| | stock | unprotected | protected |
|---|---|---|---|
| WOFF2 | 4,350,080 B | 3,966,024 B | **3,974,768 B** |
| vs stock | — | −8.8 % | **−8.6 %** |
| vs unprotected | — | — | +8,744 B (+0.22 %) |

17,502 simple glyphs quantised, **231 tail glyphs exempted** (1.3 %
of 17,932 — exactly the round-4 probe's count), 0 point-count
mismatches before and after. Peak max error:

| location | before | after | bound |
|---|---|---|---|
| wght=100 (default) | 4 | 4 | 16 |
| wght=500 | 77 | 11 | 16 |
| wght=900 | 138 | **16** | 16 |

**Verdict unchanged from round 4.** The protected single file
(3,974,768 B) is 12.1 % larger than Arm A {400,700}
(3,544,244 B) and §2 of round 4 shows two weights cover ≥ 99.8 % of
real rendered characters — so protected mode is an experimental
opt-in for the ≥ 3-weight case only, and `--instance` per weight
remains the recommended flow (the CLI says so in its output).

**Measurement-path note.** The Arm A total differs slightly by path:
3,544,244 B here (re-run) / 3,544,048 B (first run of this round,
196 B of WOFF2 jitter) vs 3,566,128 B from round 4's
`weight_cost.py` recomputation (0.6 % higher — different
instance/drop-vertical handling in that script). All three are within
0.6 % of each other and all are below the protected file, so no
conclusion moves; the `glc.py` figure is the one the tool prints.

## 日本語まとめ

ラウンド5では、デモのライブプレビューを日本語だけでなく中国語・韓国語にも対応させた。SC/KR のサブセット WOFF2 を各格子幅で生成し（中 3,302 文字・韓 2,333 文字）、フルフォントの格子幅別サイズも実測した（g8 で中 −27.3%・韓 −23.5%）。g8 での描画品質は日本語と同程度（PSNR 34〜35 dB）で、言語による外れ値はない。デモページは言語切替ボタン付きで再生成し、全 18 アセットが有効な WOFF2 でサンプル文を完全に収録していることを確認した（ブラウザでの実クリック確認はサンドボックスの制約で今回もできていない）。可変フォント側では `--quantize-variable-protected` を実装した：量子化後に fvar ピークで誤差を測り、 bound（2×格子幅）を超える尾部グリフ 231 個（1.3%）を量子化から免除して再構築・再検証する。結果、最大誤差は 138 → 16 に抑えられ、サイズ増は +0.22%（3,974,768 B、元フォント比 −8.6%）にとどまった。ただし保護後の単一ファイルは依然 {400,700} の2インスタンス合計（3,544,244 B）より 12% 大きく、実ページの 99.8% は2ウェイトで足りるため、protected モードは 3 ウェイト以上の配信用の実験的オプションとして提供し、推奨は引き続きウェイト別インスタンス化のままである。途中中断からの再開では、前ワーカーの成果を再実行で検証した（保護モードの出力 WOFF2 はバイト単位で一致）。次ラウンドの筆頭は、2026-11-12 以来更新されていない GitHub Pages のデモ再公開である。
