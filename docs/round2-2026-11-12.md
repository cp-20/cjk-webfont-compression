# Round 2 (2026-11-12): GLC becomes a tool, the two layers are measured together, and there is a demo

*A plain-language progress report. Everything numeric below was measured on real fonts in this
repository's environment; the JSON evidence is in `measure/out/`.*

## What GLC is, in one paragraph

A Japanese web font is megabytes large because it contains ~18,000 glyphs, each drawn as a list of
outline coordinates. WOFF2 already compresses those coordinates well, but it never *changes* them:
it keeps full coordinate precision, keeps tables for vertical text that a horizontal page never
uses, and for fonts stored in the older CFF format it cannot apply its best compression at all.
GLC (Glyph-Level Compression) is a build-time clean-up that runs before WOFF2 encoding: convert
CFF outlines to TrueType outlines, drop the vertical-text tables, and round every outline
coordinate onto a slightly coarser grid (at the standard setting the largest possible error is
0.4 % of the em — a fraction of a pixel at body text sizes), while keeping every glyph's bounding
box exact so line breaking does not change. The output is an ordinary WOFF2 file that every
browser already understands. A safety valve compares the result with the untouched encoding and
keeps whichever is smaller, so GLC can never make a font bigger.

## 1. Reproduction: do the published numbers hold up?

Mostly yes — and the exceptions are documented below, in this project's negative-results spirit.

| Published claim | Published | Reproduced here | Verdict |
|---|---|---|---|
| Noto Sans JP full font, stock WOFF2 | 2,302,932 B | 2,302,848 B | ✓ within 0.004 % |
| … with GLC grid 8 (ε 0.4 % em) | 1,755,656 B (−23.8 %) | 1,755,444 B (−23.8 %) | ✓ |
| … grids 2 / 4 / 16 / 32 | 2,225,392 / 1,980,856 / 1,545,836 / 1,371,932 B | 2,225,624 / 1,980,272 / 1,547,056 / 1,371,236 B | ✓ all within ±0.08 % |
| Nanum Gothic subset, stock | 61,928 B | 61,928 B | ✓ exact |
| Nanum Gothic subset, quantised grid 4 | 68,448 B (+10.5 %, stock kept) | 68,428 B (+10.5 %, safety valve kept stock) | ✓ |
| Source Han Sans JP subset, full GLC | 388,236 B at grid 8 | 380,872 B at grid 8 | ≈ (see note) |
| M PLUS 1p full font, grid 0 | 699,792 B | 699,792 B | ✓ exact |
| M PLUS 1p full font, grids 4 / 8 / 16 | 643,020 / 579,796 / 514,728 B | 666,212 / 614,540 / 559,844 B | ✗ does not reproduce |

Notes:

- **The pipeline was not fully scripted.** Every GLC script takes
  `measure/out/NotoSansJP-Regular.ttf` — a static wght=400 instance of the variable font — as an
  input, but nothing in the repository created that file. `measure/reproduce_headline.py` now does
  (varLib instancer) and re-measures every published grid; the remaining ±0.08 % wobble is
  consistent with instancing timestamps/options, not with the GLC stages themselves.
- **The Source Han number is approximate here** because the original 3,000 characters were chosen
  by token frequency over the raw page texts, which are not redistributed; this run used document
  frequency over the same pages' character sets. The stage-by-stage deltas land in the same places
  (subset+de-subroutinise 523,184 B → CFF→glyf 466,140 B → quantised 380,872 B).
- **Negative result — the M PLUS 1p quantised rows look like stale cache.** In the published
  `glc_fullsweep.json`, every quantised M PLUS row has `prep_s = 0.0`: the intermediate TTFs
  already existed when that script ran, so the sizes were inherited from an earlier state of the
  code or the font, not measured by the committed pipeline. With the committed code the font is
  still 699,792 B at grid 0 (exact match) but only reaches 559,844 B at grid 16 instead of the
  published 514,728 B. The Noto rows in the same file, whose `prep_s` values are non-zero,
  reproduce fine. Treat the M PLUS quantised row of that table as unverified; the corrected
  numbers are the ones in this document.

## 2. The new tool: `tools/glc.py`

One command replaces the scattered benchmark scripts:

```bash
.venv/bin/python tools/glc.py -i 'fonts/NotoSansJP[wght].ttf' --instance wght=400 --epsilon 0.4 -o noto.woff2
```

- Stages are flags: `--instance` (variable fonts), `--subset-file/--subset-text/--unicodes`,
  `--desubroutinize` (GLC-1), GLC-0 automatic for CFF input (`--cff-error` sets its budget),
  GLC-2 on by default (`--keep-vertical` to skip), GLC-3 behind `--canonical` (off by default —
  it measured as a wash), GLC-4 via `--epsilon PCT` or `--grid N`.
- It prints a per-stage size table and a machine-readable `--report-json`.
- The safety valve is always on unless `--no-safety-valve`: if GLC loses, the stock file is
  written instead and the tool says so. Verified live on Nanum Gothic above.
- With all stages on, the Noto headline improves slightly over the published pipeline, because
  the published full-font run never dropped the vertical tables: **1,744,720 B (−24.2 %)**.
  With `--keep-vertical` (the published stage set) it prints 1,755,704 B, matching the headline.

## 4. The interactive demo

`report/demo.html` (built by `report/build_demo.py`, linked from both reports) lets a visitor:

- paste their own text and see the estimated subset payload — stock, +GLC, and shared-base
  (cold/warm) — interpolated from subsets actually measured for this study;
- drag an ε slider and watch the same glyphs at six quantisation levels (pre-rendered by the
  pipeline), with the measured size / PSNR trade-off at each level;
- read the combined-study results table from section 3.

All numbers in the demo come from `measure/out/*.json`; estimates are labelled as estimates.

## 5. What is next
