# Round 7 — restore the GLC demo figures (2026-11-13)

Base: main `eb796de`. Branch: `round7/glc-figures`.
Comparison: freshly fetched gh-pages `b40afebbe91099e3694f0daa84143b4d39feb9ea`.

## Missing inputs and provenance

`measure/out/glc_demo.json` named six PNGs at grids 0/2/4/8/16/32,
with byte counts, but none was committed under `report/assets/`.
`report/glc_content.py` silently skips missing images, so a clean report build
lost all six figures. Before the fix, `scripts/publish_pages.sh --check`
returned 1 with only `report/glc.html` differing.

`measure/glc_demo.py` renders the committed Japanese sample strings using
FreeType without hinting at 24px, quantizes with `tools/glyphcodec.process_font`
(canonical=False), and composes a text line plus three nearest-neighbor 6x
zooms (baseline, quantized, amplified difference). The published log records
1816×344 PNGs. The JSON and measurement tables are not raster source data:
regeneration also requires the manifest-pinned Noto Sans JP font.

The generator assumed an untracked static `measure/out/NotoSansJP-Regular.ttf`
and an existing `measure/out/sweep/` directory. It now creates the directory
and, if missing, instances `fonts/NotoSansJP[wght].ttf` at wght=400, using the
same repository command as `measure/reproduce_headline.py`.

Important historical detail: the published PNG pixels still use the old
vertically mirrored formula `y = px + top - row`. Round 3 (`32f447e`) changed
the renderer to `y = px - top + row` without refreshing the embedded figures.
The new explicit `--legacy-orientation` option reproduces those historical
figures; the default retains the round-3 orientation fix. No font geometry,
measurement values, sample strings, or bitmap bearing behavior was changed.

## Regeneration

Run from the repository root:

```sh
python3 scripts/fetch_assets.py --fonts
uv pip install --python .venv/bin/python fonttools brotli pillow freetype-py
.venv/bin/python measure/glc_demo.py --legacy-orientation
python3 report/glc_content.py
```

Environment used: fontTools 4.68.0, freetype-py 2.5.1 / FreeType 2.13.2,
Pillow 13.0.0. The Noto Sans JP download matched the committed manifest SHA-256.
The general font fetch subsequently reported an unrelated Source Han subset
checksum mismatch and stopped on a derived font entry with `source_url: null`.
Neither entry is needed here; those fetcher/manifest issues remain separate work.

The six generated PNGs are committed in `report/assets/`; JSON byte counts
and the tracked generated HTML are refreshed. The existing offline publisher
integration test now requires all six assets, checks their recorded sizes,
and verifies that each complete PNG payload is embedded in generated HTML.

No PNG was extracted from live HTML as a build input. The live payloads were
decoded in memory only to compare the independently regenerated images.

## Verification and justified differences

A clean committed checkout rebuilds all three report pages without fonts,
FreeType, or Pillow: the PNGs are now committed build inputs. The publisher
itself uses `git archive HEAD`, so its check also builds from committed files.

Against freshly fetched b40afeb, `scripts/publish_pages.sh --check` returns 1,
with exactly these justified differences:

- Six `report/assets/demo_g*.png` files exist only in the rebuilt site. The
  live site embedded the images but never contained these missing source assets.
- `report/glc.html` differs only in the six base64 PNG payloads. All six decoded
  images have identical mode (L), dimensions (1816×344), and pixel bytes to live.
  Replacing just those payloads with a common placeholder makes the entire HTML
  byte-identical. PNG compression bytes differ; no visible pixels or other HTML
  changed. This is lossless image restoration, not byte-identical PNG encoding.

| Grid | Live PNG bytes | Regenerated PNG bytes |
| --- | ---: | ---: |
| 0 | 13169 | 13190 |
| 2 | 15620 | 15685 |
| 4 | 15943 | 16010 |
| 8 | 16363 | 16429 |
| 16 | 16418 | 16495 |
| 32 | 16362 | 16419 |

## What remains

No gh-pages publication or merge was performed. Publishing is a separate later
step after this fix lands. A future editorial update can regenerate upright
figures using the default renderer, explicitly accepting the visual change.
The old PNG encoder environment is not pinned, so byte-identical historical PNG
compression is not claimed. Fixing the unrelated font manifest/fetcher entries
is also outside this restoration.
