# Round 6 (2026-11-13)

## Item 3: protected mode on SC/KR variable fonts

**The JP pattern broadly carries over to these SC/KR fonts: exempting about
1–1.5% of glyphs caps the measured interpolation error for a small size
increase. The exact +0.22% price does not carry over: SC costs +0.19%,
KR +0.40%.** At grid 8, both fonts' worst sampled error falls from 138 to
16 font units. Neither protected file beats static instancing: SC is
15.53% larger than its Arm A {400,700} bundle, and KR is 13.59% larger.
For one or two weights, the recommendation remains to instance per weight;
protected mode remains an experimental option when more weights are needed.
This completes round 5 §6 item 3 only; nothing was merged or published.

### Exemption counts and errors

Full fonts, grid 8 (0.4% em at 1,000 UPM), default CLI settings: hinting
stripped, vertical metrics dropped, no subsetting or canonicalisation.
The exemption share uses the tool's non-empty simple-glyph count, matching
round 5's JP denominator. SC has 31,036 glyphs in total (31,032 non-empty
simple glyphs); KR has 24,964 (24,957 non-empty simple glyphs). Neither has
composite glyphs. Using all glyphs instead gives the same rounded shares.

| Font | Exempted / non-empty simple glyphs | Share | Simple glyphs quantised after protection |
|---|---:|---:|---:|
| Noto Sans JP (round 5 reference) | 231 / 17,932 | 1.29% | 17,502 |
| Noto Sans SC | 322 / 31,032 | 1.04% | 30,511 |
| Noto Sans KR | 379 / 24,957 | 1.52% | 24,373 |

Every sampled location is shown below. Both inputs have one fvar axis,
wght 100–900 with default 100, and gvar tuples with normalised support
(0, 1, 1). The existing `vf_sample_locations` sweep therefore covers
100 (default/minimum), 500 (midpoint), and 900 (tuple peak/maximum), exactly
as for JP. Errors are maximum absolute point-coordinate differences in
font units against the stock font, after instancing and a glyf serialization
round-trip, using `vf_glyph_errors_at`.

| Location | SC before | SC protected | KR before | KR protected | Bound (2 × grid) |
|---|---:|---:|---:|---:|---:|
| wght=100 | 4 | 4 | 4 | 4 | 16 |
| wght=500 | 77 | 11 | 77 | 10 | 16 |
| wght=900 | 138 | 16 | 138 | 16 | 16 |

Both runs report `bound_met: true`, with **zero point-count mismatches
before and after protection**. This verifies the sampled outline errors;
it is not a new visual-quality test or an exhaustive sweep of every weight.

### Delivery size: protection versus static instances

All sizes are WOFF2 bytes. Arm A uses the same CLI helper as round 5:
instance the original font at each weight, drop vertical metrics, run
`process_font` at grid 8 with canonicalisation off, then WOFF2-encode.
The {400} total is the helper's 400 entry; {400,700} sums the two files.
These full-font delivery sizes are distinct from round 5's static demo
subset/grid-reference sizes.

| Measurement | Noto Sans SC | Noto Sans KR |
|---|---:|---:|
| Stock variable WOFF2 | 7,782,072 B | 3,908,716 B |
| Unprotected variable WOFF2 | 7,101,732 B | 3,610,788 B |
| **Protected variable WOFF2** | **7,115,560 B** | **3,625,092 B** |
| Protection cost vs unprotected | +13,828 B (+0.19%) | +14,304 B (+0.40%) |
| Protected vs stock | −8.56% | −7.26% |
| Arm A {400} total | 3,026,468 B | 1,573,548 B |
| Arm A {700} (for the sum below) | 3,132,540 B | 1,617,704 B |
| Arm A {400,700} total | 6,159,008 B | 3,191,252 B |
| Protected vs Arm A {400} | +4,089,092 B (+135.11%) | +2,051,544 B (+130.38%) |
| Protected vs Arm A {400,700} | +956,552 B (+15.53%) | +433,840 B (+13.59%) |

Round 5's JP reference was +8,744 B (+0.22%) over unprotected. SC is close
in percentage terms; KR's +0.40% is about 1.8 times JP's premium, though
still small in absolute delivery cost. Across these three Noto Sans fonts,
the exemption tail stays small (1.04–1.52%) and protection reaches the same
16-unit sampled bound. That supports the qualitative pattern, not a fixed
1.3% exemption rate or a universal +0.22% size prediction for other fonts.
The static {400,700} bundle wins in all three scripts. These measurements
do not establish a break-even point for three or more weights.

### Reproduction and verification

Measured from commit `82bf62d` on branch `round6/sc-kr-protected`, using
fontTools 4.68.0. The initially absent font binaries were fetched with
`scripts/fetch_assets.py --fonts`. SC and KR both downloaded successfully
and matched `fonts/manifest.json` SHA-256 values:

- SC: `a3041811a78c361b1de50f953c805e0244951c21c5bd412f7232ef0d899af0da`
- KR: `194018e6b2b293a7964f037b25c0249ce1418bc9ab3c971060a03aa57861e252`

The bulk fetch later failed on an unrelated asset download; neither input
for this task was affected. Commands run from the repository root:

```sh
.venv/bin/python scripts/fetch_assets.py --fonts
mkdir -p measure/out/vf
.venv/bin/python tools/glc.py \
  -i 'fonts/NotoSansSC[wght].ttf' \
  -o measure/out/vf/sc_protected_q8.woff2 \
  --quantize-variable-protected --grid 8 --no-stage-sizes \
  --report-json measure/out/vf_protected_sc.json
.venv/bin/python tools/glc.py \
  -i 'fonts/NotoSansKR[wght].ttf' \
  -o measure/out/vf/kr_protected_q8.woff2 \
  --quantize-variable-protected --grid 8 --no-stage-sizes \
  --report-json measure/out/vf_protected_kr.json
```

The protected-mode pipeline itself builds and encodes the unprotected
reference, measures every sampled location, rebuilds with exemptions,
re-measures, and prices Arm A. `--no-stage-sizes` only skips extra stage
encodes. Raw results are retained in
[`vf_protected_sc.json`](../measure/out/vf_protected_sc.json) and
[`vf_protected_kr.json`](../measure/out/vf_protected_kr.json); generated
font files remain in the existing ignored `measure/out/vf/` directory.
As disclosed in round 5, small WOFF2 byte jitter is possible across rebuilds;
these are the measured sizes from this run.

Both output WOFF2 files reopen successfully, match their reported byte
sizes, retain the original glyph order and fvar axis definition, and
contain gvar, HVAR, and STAT. Vertical tables are absent as requested by
the default flow. No tool code changed. `report/glc.html` was inspected:
it carries no JP protected-mode numbers, so the requested conditional
update does not apply and that report is unchanged.

### 日本語まとめ

ラウンド5の「少数のグリフを量子化対象から外すことで、小さなサイズ増で
補間誤差を抑えられる」という傾向は、今回の Noto Sans SC/KR でも確認できた。
格子幅8で、SC は322個／31,032個（1.04%）、KR は379個／24,957個（1.52%）を
免除し、測定した全ウェイト（100・500・900）で最大誤差を16単位以下に抑えた。
最悪値は両方とも138→16、点数不一致は保護前後とも0だった。

保護後の WOFF2 は SC が7,115,560 B（未保護比 +13,828 B、+0.19%）、
KR が3,625,092 B（+14,304 B、+0.40%）。JP の約1.3%の尾部という規模感は
共通するが、+0.22%というサイズ増がそのまま一般化するわけではなく、
特に KR は約1.8倍の増加率だった。

Arm A の {400} 合計は SC 3,026,468 B／KR 1,573,548 B、{400,700} 合計は
SC 6,159,008 B／KR 3,191,252 B。保護後の可変フォントは2ウェイト合計より
SC 15.53%／KR 13.59%大きい。1〜2ウェイトなら引き続き個別インスタンス化を
推奨する。3ウェイト以上での損益分岐点や実描画品質は今回測定していない。
結果はサンプル位置の輪郭誤差についての検証であり、他のフォントすべてへの
保証ではない。HTML レポートには JP の保護モード数値がないため変更せず、
作業はタスク用ブランチに残し、マージ・公開は行っていない。
